# URL Sentry — Phishing URL/Website Detector

A minor project: a web app that classifies URLs as **phishing** or **legitimate**
using a Random Forest model trained on lexical and structural URL features,
with a human-readable explanation for every verdict.

## Project Structure
```
phishing_detector/
├── app.py                     # Flask app: routes, API, SQLite history
├── features.py                # Core feature extraction + explanation logic
├── train_model.py             # Trains and evaluates the RandomForest model
├── data/
│   ├── generate_dataset.py    # Synthetic dataset generator
│   └── phishing_dataset.csv   # Generated training data (3000 rows)
├── models/
│   └── phishing_model.pkl     # Trained model (generated by train_model.py)
├── templates/
│   └── index.html             # Web UI
├── tests/
│   ├── test_features.py       # Unit tests for feature extraction
│   └── test_app.py            # API/integration tests
└── requirements.txt
```

## Setup
```bash
pip install -r requirements.txt
python3 data/generate_dataset.py   # generates data/phishing_dataset.csv
python3 train_model.py             # trains models/phishing_model.pkl
python3 app.py                     # runs on http://localhost:5000
```

```bash
python3 -m pytest tests/ -v
```

## How It Works

**1. Feature Extraction (`features.py`)**
Every URL is converted into 17 numeric features without ever loading the
page — this keeps the tool safe to use on suspicious links. Features fall
into three groups:
- **Lexical**: URL length, dot/hyphen/digit counts, `@` symbol presence
- **Structural**: subdomain count, IP-address-as-hostname detection, HTTPS presence, shortener detection
- **Content-adjacent**: suspicious keyword matching (login, verify, secure, etc.)

**2. Dataset (`data/generate_dataset.py`)**
This environment has no live internet access to pull PhishTank/UCI/Kaggle
data, so a synthetic dataset is generated instead: legitimate URLs are built
from real Indian and global domains with realistic paths, phishing URLs are
built from six known attack patterns (IP-based, subdomain spoofing, hyphen
brand-spoofing, shorteners, embedded-brand paths, long randomized domains).

**Important for your report/viva**: the generator deliberately injects noise
— some legitimate URLs get "phishy" features (tracking params, login paths)
and some phishing URLs get "clean" features (valid HTTPS, normal-looking
TLDs) — plus direct feature-level jitter. This keeps class separation
realistic (**99% test accuracy**, not a suspicious 100%), which is what you
should expect and be ready to explain if asked. If you want to swap in a
real dataset (recommended for your final submission), download the UCI
Phishing Websites dataset or Kaggle's "Phishing Site URLs" and either use its
pre-extracted features directly, or run raw URLs through `extract_features()`.

**3. Model (`train_model.py`)**
RandomForestClassifier (200 trees, max_depth=12), evaluated with an 80/20
train/test split plus 5-fold cross-validation. `has_https` and
`has_suspicious_word` are consistently the strongest predictors — a good
talking point for your viva on which signals actually matter.

**4. Web App (`app.py` + `templates/index.html`)**
- `POST /predict` — takes a URL, returns prediction, confidence %, and top reasons
- `GET /history` — returns recent scans (stored in SQLite)
- Explanations are rule-based (not from the model directly) so the tool
  isn't a black box — this is a common and defensible design pattern for
  security tools where interpretability matters.

## Suggested Extensions (if you have time before submission)
- Swap synthetic data for the real UCI/Kaggle dataset
- Add domain-age lookup via WHOIS (needs internet access)
- Add a browser extension front-end
- Add SHAP or feature-importance visualization to the UI itself
- Log false positives/negatives from real usage and retrain periodically

## Known Limitations (be ready to state these in your viva — it shows maturity)
- No live page-content analysis (forms, iframes) — purely structural/lexical
- Trained on synthetic data; real-world phishing patterns evolve constantly
  and a production system would need continuous retraining
- No certificate-transparency or domain-age checks (would need network access)
